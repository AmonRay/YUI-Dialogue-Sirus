# Текстуры требования/награды: черновик для ведущего

Статическая трассировка текущих исходников; Lua и клиент Sirus не исполнялись. Код аддона и ассеты не изменены. Скриншот показывает широкую рамку вокруг строки, но сам предмет остаётся слева: по одному снимку нельзя утверждать, что растянута именно предметная иконка.

## Вывод

Гипотеза о пропущенной записи размеров **не подтверждается для известных локальных имён** этой цепочки. Более конкретный кандидат — `ItemButtonBackground`: файл 64×64 устанавливается в обычную текстуру `Background`, растянутую по всей кнопке, без включения нарезки. Наличие записи в `TextureSizes_335` само по себе нарезку не включает.

Скрипт `check.py` подготовлен для воспроизводимого перечисления путей и имён в обеих темах. Запуск `python research/back-reward/check.py` был отклонён исполнителем: `A worker can run only its own scripts inside its assigned files...`. Несмотря на соответствие команды назначенному пути, программного вывода нет; повторных обходных запусков не делалось. Числа покрытия и итоговый список из скрипта необходимо получить ведущему. Приведённые ниже выводы получены чтением исходников, не запуском модели.

## Резолвер и резервы совместимости

- `ThemeUtil.lua:176–230`: нормализует путь/расширение; внешние `Interface/...` возвращает без размеров (`203`); локальные файлы находит только при наличии записи размеров (если таблица загружена). Порядок: активная тема, общие категории включая GameAssets, другая тема. `Shared/` перенаправляется в `Theme_Shared/`.
- `FindTextureFile` возвращает **файл, исходную ширину, исходную высоту** (`207–208`). `GetTextureFile` намеренно возвращает **только файл** (`232–236`). Размеры доступны отдельно через `GetTextureSize` (`239–241`). Ни один метод не возвращает UV: в таблице размеров UV вообще нет.
- Неизвестное локальное имя через `GetTextureFile` превращается в `Theme_Shared/ClipboardBackground` (`168–174`). При незагруженной таблице размеров предусмотрен оптимистический путь без размеров (`216,229`); для проверки порядка загрузки ведущему нужно сверить TOC.
- `Compat_335.lua:746–805`: резерв `SetAtlas` добавляется **только если родного метода нет**. Найденный локальный файл получает UV `(0,1,0,1)` (`782–785`); это корректно для самостоятельного файла, но не может автоматически восстановить подрегион атласа. Если локального совпадения нет, резерв ищет нативный атлас и сохраняет его координаты (`789–794`). При отсутствии обоих — запасной фон. Коллизия локального имени с нативным атласом теоретически отдаст локальный файл первым; для предметного требования эта ветка вообще не вызывается.
- `SetMaskTexture` не обнаружен в Lua проекта. Фактические резервы: скрытая `CreateMaskTexture` (`332–338`), хранение ссылок `AddMaskTexture` без рендеринга маски (`478–503`), `SetMask = noop` (`507`). Они не заменяют иконку полной текстурой и не меняют её ширину. Нельзя описывать отсутствующий `SetMaskTexture` как работающий резерв.
- `Compat_335.lua:622–635` применяет `TextureFileSizes` к текстуре **только после подключения** `SetTextureSliceMargins` (`706–725`). Если размер отсутствует или UV повёрнуты — рисуется цельный файл с исходными координатами.
- `TextureSlice.lua:63–100`: отдельная псевдонарезка знает только `HotkeyBackground` (`9–12`); прочие имена рисует одним центральным слоем. Это не путь предметной кнопки. Во всплывающем окне используются `CreateLegacyPanel` (`Widget_QuestItemDisplay.lua:62,79,115,121`), где размеры/UV передаются явно (`LegacyPanel.lua:13–36`), без обращения к `TextureSizes_335`.

## Конкретный кандидат и предлагаемое исправление

1. **Приоритет: фон предметной кнопки, не поиск имени.** `DialogueUI.xml:215` задаёт `Background setAllPoints=true`; `UITemplates.lua:1407–1421` кладёт туда `ItemButtonBackground` 64×64. В шаблоне (`203–276`) нет параметров нарезки, а `OnLoad` (`1375–1385`) её не включает. Поэтому полная картинка растягивается на всю ширину строки даже при корректном резолве. Предлагается восстановить девятисегментный фон с явно выбранными отступами, либо использовать уже существующий `CreateLegacyPanel` с шириной/высотой соответствующего файла. Значения отступов определить по изображению ассета, не угадывать; отдельно учесть 256×64 для ветки выбора. Это предложение, не применённая правка и не визуально доказанная причина.
2. **Резолвер не следует заставлять автоматически возвращать или применять UV.** Он разрешает имена самостоятельных файлов; UV подрегионов уже устанавливаются вызывающим кодом. Сохранить контракт `FindTextureFile -> file,w,h`, `GetTextureFile -> file`.
3. **Усиление compat по необходимости:** развести имена локальных файлов и нативных атласов явным пространством имён/отдельным методом; при неизвестном атласе выдавать диагностику, не молча применять полный запасной фон. Проверить коллизии перед изменением порядка приоритетов. Не менять глобальный приоритет `SetAtlas` ради этой строки: её путь — прямой `SetTexture`.
4. **Длинный счётчик — самостоятельная задача вёрстки.** Проверить ширину текста `99/2048` относительно квадратной иконки; перенос к текстовой части предпочтительнее изменения размеров файла/UV. Передать решение ведущему и исследованию вёрстки.

## Передача и ограничения

Созданы только `research/back-reward/check.py` и этот отчёт. Скрипт — ограниченная Python-модель по прочитанному Lua, не интерпретатор Lua: охватывает все вызовы установки текстуры в `Widget_QuestItemDisplay` и предметном миксине `UITemplates.lua:1373–1913`, раскрывает известные ветки имён и четыре суффикса GameAssets; произвольные данные API оставляет неизвестными. Размеры, показанные моделью для `GetTextureFile`, означают дополнительный поиск через `FindTextureFile`, а не дополнительные возвращаемые значения Lua-функции.

Ведущему осталось: запустить скрипт и сверить вывод; проверить загрузку таблицы до резолва; снять реальные `GetQuestItemInfo`/размеры регионов в клиенте; осмотреть ассеты рамки и фона; проверить обе темы, широкую кнопку, длинный счётчик и выбор награды в Sirus. Сборки, проектные тесты и игровые проверки здесь не выполнялись. Черновик не является подтверждением исправления проекта.
