* `Code/Dialogue/DialogueUI.lua:1564–1654`: на странице подробностей `FormatQuestText` определяет начальный `offsetY`, а заголовок и сетка наград формируются позже; `SetScrollRange(offsetY)` должен включать их в прокрутку. `:3104–3200` размещает награды. `Code/Dialogue/DialogueUI.xml:364–573` определяет `DUIQuestFrame` и контейнеры содержимого/прокрутки; `:235–240` задаёт **отдельный** `maxLines="2"` имени предмета — этот лимит нельзя бездумно считать лимитом основного текста. Снимок показывает многоточие после «Твоя награда жд...», но по изображению нельзя отличить сокращение исходной строки от усечения FontString.

## Как пользоваться после согласованной правки

1. Ведущий может запустить из корня `python research/quest-text-wrap/check_contract.py`. Скрипт создаёт `cases.json` (90 комбинаций), `results.json` и печатает самопроверку оракула и инвентарь API/XML. **Без наблюдений возвращает код 2, а не успех переноса.** Он не выполняет Lua и не имитирует движок WoW.
2. В Sirus открыть задание с оригинальной строкой, затем воспроизвести тексты из `cases.json` разрешённым тестовым источником данных. Для каждой ширины 220/358/520 UI-единиц, масштаба 0.75/1/1.5 и размера шрифта 12/18 измерить `GetText`, доступную ширину, фактические границы строк и высоту FontString после раскладки; вручную убедиться в видимости конечного маркера (отдельно от `GetText`). Проверить также Detail, Progress, Complete, Greeting; где есть награды, снять `reward_top`, `reward_bottom`, `content_height`. Для `short_after_long` переиспользовать **тот же** объект после длинного текста, затем снова открыть длинный текст.
3. Сохранить наблюдения как JSON-массив объектов с `id` из `cases.json` в этой папке (например `observations.json`), запустить `python research/quest-text-wrap/check_contract.py research/quest-text-wrap/observations.json`. Обязательные поля заданы в `validate` в скрипте: `raw_text`, `last_marker_visible`, `explicit_breaks_preserved`, `added_ellipsis`, `measured_after_layout`, `available_width`, `effective_scale`, `font_size`, `rendered_lines` (массив объектов `{ "width": число }`), `measured_height`, `allocated_height`, `text_top`, `text_bottom`, `reward_top`, `reward_bottom`, `content_height`; короткому тексту также нужны `same_object_reused`, `prior_text`, `prior_allocated_height`, `prior_reward_top`. Координаты — UI-единицы вниз от верха содержимого. Случаи с отсутствующими наблюдениями остаются неподтверждёнными даже при нуле ошибок. Переходы между измерениями ширины и шрифта выполняются на том же открытом окне, а не только после полной пересборки.
4. Проверить прокрутку до конечного маркера и последней награды при минимальном окне, а также при уменьшении/увеличении ширины и при возвращении к короткому заданию; сравнить показанный текст с возвращаемой исходной строкой API и буфером копирования. XML-имена из `results.json` и публичные функции из частичного инвентаря сравнить с исходной ревизией; наличие имён само по себе не является полной проверкой совместимости.

Скрипт проверяет фактически записанные измерения и инварианты (полный текст, строки в доступной ширине, высота, отсутствие перекрытия, сокращение высоты при переиспользовании, монотонность для разных ширин/шрифтов). `rendered_lines`, конечный маркер и явные переводы строк требуют **независимого визуального наблюдения**, а не вычисления из исходного текста. Принятое допущение: локальная подмена текста доступна проверяющему; сам скрипт не вмешивается в API клиента и не меняет Lua. Если Sirus не позволяет подменить реальные данные задания, матрицу можно выполнить только на отдельном испытательном UI; это не заменяет воспроизведения именно исходного задания и проверки его полного текста в клиенте.
